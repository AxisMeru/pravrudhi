# Baseline for scripts/check_no_secrets_in_diff.py -- waivers for token-shaped strings that are known not
# to be live credentials, or that are live-shaped but already revoked and permanently published.
#
# READ THIS FIRST. Two things about this file are deliberate and neither is negotiable:
#
# 1. IT CONTAINS NO SECRETS, AND CANNOT. Each entry is keyed on
#    `sha256(<repo-relative path> NUL <matched text>)`, truncated to 16 hex characters -- never on the
#    value. A waiver file that listed literal token values would be the leak it exists to manage, which is
#    the one place this file differs on purpose from scripts/fail_open_defaults_baseline.txt (that one keys
#    on the matched expression, because a fail-open default is not a secret). The guard PRINTS the key for
#    every finding, so adding a waiver is copy-and-paste from the failing CI log; nobody ever handles the
#    value to write a line here.
#
# 2. A KEY WITH NO REASON WAIVES NOTHING. The guard reports a bare key as a problem and keeps failing. The
#    reason is for the next reader: say what the value is, when and by whom it was established not to be
#    live, and where that is recorded.
#
# FORMAT: `<16 hex characters>  <reason>`, one per line. `#` comments and blank lines are ignored. The key
# digests the PATH together with the VALUE, so a waiver does not follow the value into another file and
# does not survive the file being renamed. Stated consequence, rather than hidden: one key waives every
# occurrence of that same value in that same file (in this repo, one entry covers two lines).
#
# A stale key -- one that no longer matches anything in a whole-tree audit
# (`--all-tracked`) -- is printed as "remove this line", so this file shrinks as the findings go away
# instead of quietly outliving them.
#
# ON THE TWO INCIDENTS THIS GUARD EXISTS BECAUSE OF, neither of which needs an entry here, stated so that
# their absence does not read as an oversight:
#   * 2026-09-26, the Docker build ARG that leaked a GitHub PAT into a local BuildKit log. The value was
#     never committed to this repository, so it is in no diff and no tree, and there is nothing to waive.
#   * 2026-09-11, the Telegram bot token committed in a tracked, published file. It has been rotated and
#     the old value now returns 401, but it is permanently in this repository's public history. It is NOT
#     in main's tree (verified: a whole-tree audit of main reports no telegram-bot-token hit) and it is
#     therefore in no future PR's diff either, so it needs no waiver. It is not in this file for a second
#     reason as well: computing its key would mean handling the value, and this guard is built so that
#     nobody has to. It IS what this guard's patterns were calibrated against -- a whole-tree audit at
#     85ad860 finds it, which is how the leading-`\b` anchoring bug (see the guard's RULES comment) was
#     found and fixed.
