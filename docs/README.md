# Documentation index

The code documentation is Sphinx, in `sphinx/` (build it with `cd sphinx && make html`; see
[sphinx/narrative/development.md](../sphinx/narrative/development.md)). This folder holds the written documents.

| Document | What it is |
|---|---|
| [usage.md](usage.md) | Using Pravrudhi: what a night does, what you can change, reading the evidence, more machines and coding agents. |
| [architecture.md](architecture.md) | The kernel/engine split, what a night is, the sealed pool, the sequential boundary. |
| [client.md](client.md) | The Python client for talking to a running engine. |
| [DESKTOP.md](DESKTOP.md) | The macOS desktop build and installation. |
| [LOOM.md](LOOM.md) | Loom model pipelines: compiling a plan without I/O or GPU work. |
| [BAND.md](BAND.md) | Choosing how hard the engine keeps working on an external artifact. |
| [api/](api/) | The partner API: quickstarts, the OpenAPI contract, the reason codes. |
| [adr/](adr/) | Architecture decision records. |
| [evidence/](evidence/) | Evidence documents rendered from the ledger; regenerated by `make reproduce`, never edited by hand. |
| [PRD.md](PRD.md), [ROADMAP.md](ROADMAP.md) | Product requirements and the roadmap. |
| [spec.md](spec.md) | The evolution log. |

Generated reference pages (the command line, configuration files, environment variables, HTTP routes and the module map)
are in `sphinx/reference/` and are checked against the code in CI.
